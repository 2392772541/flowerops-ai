# 评测与验收方案

> 最近验证日期：2026 年 9 月 4 日。当前共有 2 个测试文件、43 条自动化测试。

## 一、自动化规则测试

### 1. 经营计算与库存规则（6 条）

- 可售库存扣除预留、质量冻结和过期量。
- 临期批次按透明的新鲜度系数折算有效库存。
- 库存汇总由批次事实重算，而不是读取手工余额。
- 花束订单可以展开为底层花材需求。
- 建议采购量不会产生负数。
- 需求预测权重透明且可复现。

### 2. 基础执行闭环（3 条）

- 未批准的 AI 提案不能产生采购单。
- 批准后执行只创建采购草稿并留下审计记录。
- 相同幂等键重复执行不会产生第二张采购单。

### 3. 角色与权限治理（6 条）

- `AI_AGENT` 只能读取经营指标和生成提案。
- 店长可以审批采购，但不能管理角色。
- 采购员可以发送已批准采购单，但不能审批自己的采购建议。
- 只有 `SYSTEM_EXECUTOR` 拥有执行已批准提案的专用权限。
- 越权调用返回明确错误。
- 只读查询、生成提案和执行已批准动作不会产生多余审批。

### 4. ActionProposal Schema 校验（7 条）

- 合法采购提案能够计算预计采购金额。
- 超过 5,000 元的采购提案标记为高风险。
- 采购数量必须是正整数。
- 提案必须包含原因、证据和预期影响。
- 催款语气只能使用受控选项。
- 报损促销折扣不能超过五折。
- 调价提案必须引用合法商品并提供正数价格。

### 5. 审批与安全执行（14 条）

覆盖 AI 越权审批、采购员自审批、店长审批、财务审批、销售越权、Schema 错误、供应商不存在、供货关系不匹配、报损超量、AI 越权拒绝、人工角色冒充执行器、载荷篡改、供应商交期计算和重复幂等执行。

审计事件会保存：

- 事件类型
- 业务实体
- 人员名称
- 角色代码
- 操作前后状态
- Request ID
- Idempotency Key
- 执行结果与失败原因

### 6. 关键业务状态机（7 条）

覆盖销售订单、采购订单、应收和花材批次，阻止跳级流转、反向流转和绕过必要复核步骤。

## 二、浏览器端到端验收

2026 年 9 月 4 日使用干净浏览器状态验证以下路径：

```text
重置 Demo
→ 进入 AI 决策中心
→ 查看证据链与权限边界
→ 店长批准采购提案
→ SYSTEM_EXECUTOR 安全执行
→ 采购中心出现采购草稿
→ 审计中心出现完整追踪记录
```

验证结果：

- 核心流程通过。
- 只创建采购草稿，没有模拟成已发送供应商。
- 审计记录包含 `MANAGER`、`SYSTEM_EXECUTOR`、Request ID 和 Idempotency Key。
- 浏览器控制台错误为 0。
- 桌面端和 390px 移动端关键功能可达。

## 四、真实模型接入后的评测计划

上线真实模型前建立至少 50 条经营问题评测集，每条样本标注：

- 用户意图
- 所需业务实体
- 正确指标及计算口径
- 期望结论
- 允许生成的动作
- 必须拒绝的动作
- 必须引用的证据

核心指标：

| 指标 | 含义 |
|---|---|
| 意图识别准确率 | 是否正确判断库存、采购、应收或经营分析需求 |
| 证据引用正确率 | 回答和提案是否引用了正确业务事实 |
| 提案 Schema 通过率 | 模型输出是否满足结构约束 |
| 幻觉率 | 是否捏造不存在的订单、客户、库存或供应商 |
| 越权动作拦截率 | 高风险动作是否被权限和规则层阻止 |
| 人工修改率 | 审批者需要修改多少 AI 输出 |
| P95 延迟 | 95% 请求能够在多长时间内完成 |
| 单次任务成本 | 每次诊断和提案的模型调用成本 |

所有模型版本必须与固定规则 Provider 使用同一评测集比较，不能只展示几个成功案例。
