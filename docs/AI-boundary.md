# AI 权限、风险与安全边界（v2.0）

## 1. 总原则

> 事实由确定性系统计算，模型负责解释和候选方案，规则负责硬约束，人负责高影响判断，执行器负责正确落地。

## 2. 模型可以做什么

- 阅读经过权限裁剪的经营事实快照。
- 解释缺货、临期、应收和数据质量异常。
- 生成满足 Schema 的候选方案与可编辑草稿。
- 明确列出证据 ID、假设和不确定性。

## 3. 必须人工批准

- 采购数量、供应商与预算确认。
- 调价、折扣、促销和报损。
- 催款内容、发送对象和发送时机。
- 大额库存占用、释放、调拨或其他高影响动作。

## 4. 永远禁止模型自行执行

- 修改库存余额、伪造到货、删除流水。
- 标记收款、核销坏账、修改客户账期。
- 修改供应商账户、用户角色或权限。
- 跳过审批、覆盖历史记录或直接发送外部消息。
- 把无法验证的推测写成经营事实。

## 5. 四层机器防护

1. **结构层**：JSON 可解析并通过 Zod Schema。
2. **证据与实体层**：证据完整，供应商、商品、订单、客户和批次存在且关系有效。
3. **经营策略层**：动作类型、数量、金额、折扣等在白名单与红线内。
4. **执行层**：状态、角色、载荷完整性和幂等键再次校验。

## 6. 角色矩阵

| 角色 | 允许 | 禁止 |
|---|---|---|
| OWNER | 全部经营审批与权限管理 | 绕过审计改历史流水 |
| MANAGER | 批准采购、调价、报损和催款草稿 | 管理角色、冒充执行器 |
| PURCHASER | 生成建议、处理已批准采购草稿 | 批准自己的采购建议 |
| WAREHOUSE | 维护批次、预留和释放 | 自行报损或调价 |
| SALES | 查看经营事实、生成建议 | 批准采购或催款 |
| FINANCE | 应收、账期和催款相关审批 | 审批采购、修改库存 |
| AI_AGENT | 只读分析、生成候选提案 | 批准、拒绝或执行写入 |
| SYSTEM_EXECUTOR | 执行人工已批准且复验通过的提案 | 生成或批准提案 |

## 7. 失败案例与处理

- 错误 JSON：拒绝解析并记录失败类型。
- 模型超时：安全降级至规则基线，禁止自动外部写入。
- 虚构供应商：实体白名单拒绝进入审批。
- 折扣超过 50% 演示红线：策略层阻断并要求人工重拟。
- 批准后载荷被篡改：执行前复验失败并写失败审计。
- 重复提交：相同 Idempotency Key 不产生第二张草稿。

## 8. 数据与隐私

当前数据全部合成。真实试点时只采集完成任务所需字段，业务数据脱敏，提示词与日志避免包含联系人、支付账户和非必要客户信息；模型供应商、数据留存和跨境问题需单独评审。

## 9. Demo 与生产的区别

Demo 只创建本地草稿与审计记录，不代表真实采购已发送、库存已扣减或客户已收到消息。生产外部副作用需通过服务端权限、事务/Outbox、重试、补偿、告警和人工撤销流程。
