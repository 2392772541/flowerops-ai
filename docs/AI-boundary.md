# AI 权限与安全边界

## 可自动执行

- 读取和聚合经营数据
- 发现异常、生成图表和解释
- 生成需求预测与采购建议
- 创建采购、催款、调价和报损草稿

## 必须人工批准

- 采购确认与发送供应商
- 修改销售价格
- 发送催款消息
- 大额库存占用、释放或调拨
- 退款、报损、客户账期调整

## 永远禁止 AI 自行执行

- 直接修改库存余额、伪造到货或删除流水
- 将未收款标记为已收、核销坏账
- 修改供应商收款账户、用户角色或权限
- 跳过审批或覆盖已结账记录

## 控制措施

1. 写操作白名单：执行器只识别明确的 ProposalType。
2. 状态校验：只有 APPROVED 状态可执行。
3. 幂等：相同 idempotencyKey 只产生一次正式结果。
4. 人审：展示证据、风险、负载和预期影响后审批。
5. 审计：保留 actor、时间、前后状态、requestId 和结果。
6. 最小副作用：Demo 只创建草稿，不对外发送或真实扣减库存。


## 角色权限矩阵

| 角色 | 可做什么 | 明确禁止 |
|---|---|---|
| OWNER（老板） | 全部经营审批、权限管理 | 不能绕过审计直接改历史流水 |
| MANAGER（店长） | 批准采购、调价、报损和催款草稿 | 不能管理角色，不能冒充系统执行器 |
| PURCHASER（采购） | 生成采购建议、发送已批准采购单 | 不能批准自己的采购提案 |
| WAREHOUSE（仓管） | 预留和释放库存 | 不能自行报损或调价 |
| SALES（销售） | 查看经营数据、生成建议、预留库存 | 不能批准催款或采购 |
| FINANCE（财务） | 催款、账期和核销相关操作 | 不能审批采购或修改库存 |
| AI_AGENT（规则 AI） | 读取指标、生成 ActionProposal | 不能审批、拒绝或执行任何业务写入 |
| SYSTEM_EXECUTOR（系统执行器） | 执行已经人工批准且复验通过的提案 | 不能生成或批准提案 |

## 三重校验

每个提案在人工批准前必须经过：

1. **Schema 校验**：数量、价格、枚举值和必填字段符合约束。
2. **业务实体校验**：供应商、商品、客户和批次真实存在，且关联关系有效。
3. **角色权限校验**：例如采购员不能审批自己的采购提案，AI_AGENT 永远不能审批。

执行前再次校验，防止提案获批后载荷被篡改。校验失败进入 `VALIDATION_FAILED`，不产生采购、库存或外部消息写入，并生成失败审计事件。
