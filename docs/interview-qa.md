# AI 产品经理面试追问与回答（v2.0）

## 1. 为什么选择鲜切花？是不是为了编故事？

鲜切花同时包含易腐批次、配方消耗、订单波动、供应交期和应收账期，能在个人项目可控制范围内展示跨模块决策。但我没有把行业特征当作用户证据：真实需求强度仍需访谈验证。

## 2. 为什么把用户收窄到批零一体商家？

原版把批发、社区花店和花艺工作室放在一起，工作流过宽。v2.0 选择同时承担销售、采购和库存判断的经营负责人，让临期/缺货场景和决策责任更一致。其他类型进入后续研究，不强行共用一个 MVP。

## 3. 哪部分必须用模型？

严格说，当前闭环用规则也能完成，所以规则是基线。模型的潜在价值在于把跨模块事实解释成自然语言、比较多个候选方案、生成可编辑沟通草稿和处理开放表达。库存、金额、日期、权限和硬约束不需要模型。

## 4. 为什么不直接接真实大模型？

GitHub Pages 是静态前端，放 API Key 不安全；随机输出也会让面试演示不可复现。当前用固定回放验证输出契约、防护和评测框架。下一步通过服务端 OpenAI-compatible Provider 接入真实模型，并保存模型、Prompt、数据集、延迟和成本版本。

## 5. 规则基线 100%，是否说明不需要模型？

它只在十条预设、边界明确的样例上 100%，不代表能理解真实开放问题。基线的作用是确定最低可靠能力和故障降级。真实模型必须在开放表达、多方案质量和人工修改率上证明增量价值，否则不该引入。

## 6. 混合方案也是 100%，是不是过拟合？

是设计样例内的结果，所以文档明确限制外推。它证明校验和降级按预期工作，不证明真实模型质量。下一步需要独立扩充 80+ 样例、双人标注、冻结测试集，并记录错误分布。

## 7. 合成数据到底验证了什么？

验证字段关系、计算口径、交互闭环、权限、状态机、异常处理和评测代码能运行。不能验证用户价值、真实数据分布、模型准确率、性能、收入或降本。

## 8. 如果模型虚构供应商怎么办？

模型只返回实体 ID。审批前校验证据和目标实体是否存在，以及供应商与商品关系是否有效；未知实体直接阻断。执行前再校验一次，防止批准后载荷被篡改。

## 9. 为什么折扣限制放在业务层，不放 Schema？

Schema 只验证它是不是合法比例格式；“不超过 50%”是可配置经营策略。分层后能区分格式错误和业务越界，也便于不同商家配置不同红线。

## 10. 为什么 AI 不能直接执行？

采购、调价、催款和报损涉及资金、履约和客户关系。概率模型负责缩小决策空间，授权人承担业务判断，确定性执行器负责正确写入。低风险自动化也需要真实试点证明后逐步开放。

## 11. 如何避免重复下单？

每个提案带 Idempotency Key。执行器记录已处理键，相同键再次提交只返回已处理结果并记录审计，不创建第二张草稿。

## 12. 怎么衡量模型价值？

先比较规则、人工和模型：任务完成时间、证据正确率、建议采纳率、人工修改率、拒绝原因、P95 延迟和单次成本。只有模型相对基线带来稳定增量且不突破安全门槛，才扩大范围。

## 13. 怎么衡量业务价值？

试点前记录决策耗时、缺货、临期损耗、周转、毛利和逾期周期基线；先影子模式，随后灰度比较。当前项目没有真实业务收益数据，所以不写改善比例。

## 14. 用户研究怎么做？

访谈 5–8 位目标经营者，追问最近一次真实缺货/临期决策、使用的表格和聊天记录、可信数据、审批人、错误后果与耗时。至少三位独立提到同一高频问题，才升级为已验证需求。

## 15. 真实上线最大的风险是什么？

数据质量比模型表达更关键：错误批次、缺失效期或未同步订单会让正确推理建立在错误事实之上。因此要先做数据质量阻断、影子模式和可观测性，再讨论自动化。

## 16. 你作为产品经理而不是工程师做了什么？

我做了场景收敛、JTBD、证据边界、方案对照、AI/规则/人工职责划分、PRD、权限与失败策略、评测指标、实验记录和面试演示路径；代码是为了让这些产品决策可运行、可复现，而不是单纯展示技术栈。

## 17. 如果只能继续做一件事？

先做真实用户访谈和一次影子决策观察。它能决定场景是否成立、字段是否真实、风险边界是否被用户接受，也决定是否值得继续投入真实模型。
