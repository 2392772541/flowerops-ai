# AI 产品经理面试讲解脚本（v2.0）

## 30 秒版本

我做的是 FlowerOps AI，一个面向小型鲜切花批零一体商家的受控经营决策实验。这个行业的库存价值会随批次效期变化，花束订单还要展开到花材需求。我的核心不是做一个聊天壳，而是把经营事实、模型候选、规则校验、人工审批、幂等执行和审计串成闭环。在线版用合成数据和固定模型输出回放，不伪造真实客户或收益，重点证明我能定义模型边界、设计失败处理并建立可复现评测。

## 1 分钟版本

我先把原来覆盖批发、社区花店和工作室的宽泛定位，收窄到小型鲜切花批零一体商家的店长。成熟 ERP 已经能做补货阈值和库存记录，所以库存、金额、日期与配方仍由确定性领域引擎计算；生成式模型只负责解释异常和生成结构化候选。候选必须通过 JSON Schema、证据、实体和经营策略校验，采购、折扣、催款和报损必须由人批准，再由独立执行器二次复验并幂等落地。为了证明不是只演示成功案例，我做了五种模型故障回放和十条三方案评测，并用 53 条测试覆盖业务和治理规则。

## 3 分钟现场演示

### 0:00–0:25｜面试导览

先展示项目真实性声明、核心用户、我的职责和非目标：这是独立研究原型，不是已上线 SaaS；用户访谈、真实模型效果和业务收益仍待验证。

### 0:25–0:55｜经营事实

在经营总览说明订单额、毛利、有效库存和采购资金占用都由当前合成数据现场计算。强调“不让模型算库存和金额”。

### 0:55–1:30｜模型实验室

优先运行三个场景：

1. 虚构供应商：未知实体在审批前被拦截。
2. 折扣越界：合法 JSON 仍可能违反经营策略，因此业务校验独立存在。
3. 模型超时：切换规则基线，但仍只生成待审批草稿。

这部分是项目与普通 AI Demo 的主要差异。

### 1:30–2:05｜离线评测

切换规则基线、纯模型回放和混合方案。解释纯模型回放的场景通过率 20%、不安全动作率 40% 是刻意保留失败样例的结果；混合方案在当前 10 条设计样例中通过，不代表真实模型线上成绩。

### 2:05–2:40｜审批与执行

打开采购提案，查看证据、公式、Payload 和风险。由 `MANAGER` 批准，再由 `SYSTEM_EXECUTOR` 执行。采购中心只能出现 `DRAFT`，没有伪装成已向供应商下单。

### 2:40–3:00｜审计与收尾

展示审批、执行、Request ID 和 Idempotency Key。说明重复执行不会产生第二张采购草稿。

收尾句：

> 我想证明的不是模型能生成一段漂亮建议，而是当模型出错时，产品仍然知道事实是什么、谁来决定、什么能执行，以及如何追责。

## 我的职责

- 桌面研究、用户范围收敛、JTBD、非目标和假设台账。
- 领域模型、业务规则、状态机和权限矩阵。
- 模型介入点、Prompt 输出契约、失败分类和降级策略。
- 评测集、指标、基线、回归测试与实验记录。
- React 原型、GitHub Pages 发布和跨端验收。

## 关键取舍

- 不把成熟 ERP 的补货规则包装成 AI。
- 不在浏览器保存 API Key；在线版使用固定输出回放。
- 不删除规则 Provider，它是基线与故障降级。
- 不写未经验证的收益数字；只展示可复算情景。
- 不让模型直接执行；高影响动作必须人工批准。
